# 🦟 EPISENCE — Feature List & Details

This document outlines the complete feature set of the EPISENCE platform, detailing what each feature is, how it works, and its technical implementation based on the PRD.

---

## 1. Role-Based Authentication System
**What it is:** A secure login and registration system that controls access to the platform based on user roles (Admin, Health Officer, Citizen, Guest).
**How it works:**
- Users register or log in via the frontend auth UI.
- The backend validates credentials and issues a JSON Web Token (JWT).
- The token is stored locally and attached to subsequent API requests.
- Protected routes on the frontend and backend verify the token and the user's role before granting access.
**Technical Details:** FastAPI, python-jose (JWT), passlib (bcrypt), Zustand (frontend state).

## 2. Institutional Government UI Theme
**What it is:** A professional, clean design language modeled after real government health dashboards (like IDSP, CDC) rather than typical flashy hackathon projects.
**How it works:**
- Uses a specific color palette featuring Prussian Blue, Steel Teal, Burnished Gold, and warm off-white (Parchment) backgrounds.
- Implements strict design rules for typography (Outfit/Inter), subtle borders, and structured data tables.
- Includes a subtle tri-band header and monochrome line-art emblems.
**Technical Details:** Tailwind CSS v4, Lucide React icons, standard CSS variables.

## 3. Interactive Risk Heatmap
**What it is:** A dynamic map displaying disease risk zones across the selected region.
**How it works:**
- Renders an interactive map using Leaflet.
- Displays colored heat zones or markers indicating the risk level (Low, Moderate, High, Critical) of specific areas.
- Clicking on a zone marker opens a popup or redirects to a detailed view of that zone's current statistics.
**Technical Details:** React-Leaflet, Leaflet.heat, OpenStreetMap tiles.

## 4. Real-Time Command Dashboard
**What it is:** The primary interface for health officials, summarizing the current state of disease surveillance.
**How it works:**
- **Stat Cards:** Displays key metrics like total active zones, new alerts, average risk, and case counts.
- **Weather Integration:** Shows live weather data (temperature, humidity, rainfall) for selected zones, fetched via OpenWeatherMap.
- **Alert Ticker:** A scrolling feed of recent critical alerts generated by the risk engine.
**Technical Details:** React components, Recharts for mini-trends, OpenWeatherMap API integration.

## 5. Community Water Reporting (with Live Updates)
**What it is:** A feature allowing citizens to report stagnant water or potential mosquito breeding grounds.
**How it works:**
- Citizens access a form that auto-detects their GPS location or allows them to pin a location on a map.
- They submit details and a severity level.
- Upon submission, a WebSocket event (`new_report`) is broadcasted to all connected clients.
- The dashboard map updates instantly to show the new report marker without requiring a page refresh.
**Technical Details:** HTML5 Geolocation API, FastAPI WebSockets, Custom frontend `useWebSocket` hook.

## 6. Hospital Case Tracking & Trends
**What it is:** Tools for monitoring disease cases reported by local hospitals.
**How it works:**
- Health Officers input or upload daily case counts categorized by disease type (Dengue, Malaria, etc.).
- The system stores this historical data.
- The frontend visualizes this data using interactive line charts and detailed tabular views, allowing officials to spot rising trends.
**Technical Details:** JSON local storage (backend), Recharts (frontend visualization).

## 7. Hybrid Risk Scoring Engine
**What it is:** The core intelligence of EPISENCE, combining rule-based logic and Machine Learning to assess and predict disease risk.
**How it works:**
- **Rule-Based Fallback:** Calculates a composite score based on weather (30%), water reports (25%), and hospital cases (45%). Provides explainability ("factors").
- **Current Risk Classification:** Uses an XGBoost model trained on historical data to classify the current risk level of a zone into one of four tiers.
- **Future Forecasting:** Uses a Prophet time-series model to predict the composite risk score 7 to 14 days into the future.
- When new data arrives, the engine recomputes scores and triggers alerts if critical thresholds are crossed.
**Technical Details:** scikit-learn, XGBoost, Prophet, Python API endpoints.

## 8. Progressive Web App (PWA) Capabilities
**What it is:** Features that make the web application behave like a native mobile app.
**How it works:**
- Users can "Install" the dashboard to their mobile or desktop home screen.
- A service worker caches critical static assets, allowing the UI shell to load even without an internet connection.
- Provides an offline fallback page if the backend API is unreachable.
**Technical Details:** vite-plugin-pwa, Workbox, web app manifest.

## 9. Real-Time WebSocket Infrastructure
**What it is:** The underlying communication layer enabling instant UI updates.
**How it works:**
- When the frontend loads, it establishes a persistent WebSocket connection with the backend.
- The backend broadcasts events like `new_report`, `alert_created`, and `risk_updated`.
- The frontend listens to these events and updates global state (Zustand) or triggers toast notifications, keeping all users synchronized with live data.
**Technical Details:** FastAPI WebSocket endpoints, React `useWebSocket` custom hook.
